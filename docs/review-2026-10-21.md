# PO Tracker review and cleanup (2026-10-21)

## Summary

I read all of `index.html` (about 3,650 lines), `sw.js`, the manifest and the README. I found **13 bugs** and confirmed every one by reproducing it against the code as it was before this work (commit `7339270`). The worst ones lost logged time without any warning. All 13 are fixed.

I also reworked the workflow around the three jobs the app does:

- entering orders
- tracking time
- organizing orders

There is now a suite of **53 end-to-end tests**, and all of them pass. I ran the suite 3× in a row with no flaky results.

The barcode scanner code was **not touched**. The last commit restored a known-working scanner, so I left it alone.

Smaller issues fixed along the way:

- Tag names were inserted into order cards as raw HTML, so a tag like `<img onerror=…>` would run. They're now escaped.
- Pausing and resuming made the next ± adjustment display wrongly: the pause counted as "started later".
- Dragging or editing an adjustment on the timeline updated the timeline position but not the time shown in the session list.
- Bulk "+5m" adjustments were stored with mismatched times, so they showed in different places on the timeline and in the session list.
- "Overlaps with running timer" was never checked for split timers, and sessions on finished orders were ignored when checking overlaps.
- The lunch and end-of-day notifications crashed on browsers without the Notification API (`Notification.permission` was read without checking that it exists).
- Swiping between tabs did nothing while a single timer ran, but worked during a split timer. It also switched tabs behind open dialogs.
- Bug found by the new tests: the Restore confirmation opened *behind* the Settings sheet, so it couldn't be tapped.

## 2. Workflow changes

### Entering orders
- **PO first.** Step 1 is now scan or type the PO. Step 2 is optional tags and notes, then **▶ Start Timer** or **Save Without Timer**. It used to be tags → scan → confirm → start, which was three screens before the timer ran.
- **Duplicate detection.** Matching ignores case and stray spaces.
  - If the PO is already active, you get **Start timer on it**, **Open order** or **New anyway**.
  - If it's archived, you get **Reopen it** or **New order anyway**.
- **Split Time:**
  - a hint explains exactly how the time will be divided
  - duplicate entries are refused with a message
  - a PO that already exists gets the time added to it instead of being duplicated

### Tracking time
- **One timer at a time, never lost.** Anything that would start a new timer while one is running opens a "Stop Current Timer?" sheet first: starting another order, resuming a group, a bulk split, or finishing the order being timed. Save (with or without CNF) and the next action continues. Close the sheet and nothing changes.
- **Timer has its own screen.** "+ New" always starts a new order, even while timing. On every other screen a bar at the top shows the running PO and elapsed time; tap it to return. It turns amber when paused.
- **Alerts:**
  - Lunch and end-of-day times both come from Settings; **End-of-day alert** is a new setting that defaults to 16:00.
  - Each alert fires once per day.
  - If the phone slept through an alert, the timer is paused *at the alert time*, not when you reopen the app.
  - A timer started after the alert time isn't affected.
  - New **Stay paused** button on the alerts.
- **Stats:** today's minutes include the running timer.

### Organizing
- **Sort:** Newest, Last worked, Oldest, PO # (natural order, so 9 < 10 < 100), Most time. Your choice is remembered. Favorites and the order being timed stay at the top.
- **Filter chips:** ★ Favorites and ⚠ Unconfirmed, both with counts, plus one chip per tag in use.
- **Search** now also covers notes. The header shows "Showing X of N".
- **Select** button for bulk actions (long-press still works), with **Select all**. Bulk buttons are disabled while nothing is selected.
- **Order detail:**
  - edit **PO number and notes** (fixes typos; refuses a PO already used by another active order)
  - **Delete order**, with confirmation
  - "Mark Finished" warns about sessions that aren't CNF'd yet
- **Cards** show "Last worked …" instead of the created date once there's time logged.
- **Archive:** sorted by finish date, shows a count, has a Select button, and Delete is confirmed.

### Data safety
- **Restore a JSON backup** in ⚙ Settings → Backup & Restore. Before this, backup was one-way.
  - The file is validated first.
  - The confirmation shows what will be replaced.
  - Restore is blocked while a timer runs.
- Stored data is repaired on load, so one damaged record can't break the app.
- If the device runs out of storage, saving now shows an error instead of failing silently.
- **CSV export** now has local **Date / Start / End** columns plus Split Qty and Finished. The old export had one UTC timestamp, which was the wrong day for evening work.
- Settings now holds everything that isn't a statistic: backup/restore, persistent storage, notification test and app version. The Stats tab is just stats.

  - `setOrdersTabDisabled`

## 6. Recommendations (not done)
- **Show the running timer on the Timeline** as a live block. Today it only appears once it's stopped.
- **The background alerts in `sw.js` use `setTimeout`.** Android can kill the service worker, so those notifications aren't guaranteed; the in-app catch-up added here covers the timer itself. Reliable background alerts would need a server-sent push notification or Android's experimental Notification Triggers.
- **Remind you to back up.** Data is localStorage-only. A prompt after N days without a backup would be cheap insurance.
- **Inline styles:** most markup still uses inline `style="…"`. Moving them into classes would make future visual changes much easier. It wasn't done here to keep the change reviewable.
- **Zoom:** `user-scalable=no` blocks pinch-zoom. That's fine for a shop-floor app, but worth knowing for accessibility.
